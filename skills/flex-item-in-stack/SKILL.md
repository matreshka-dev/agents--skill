# `flexItem` в Matreshka BFF

## Где работает

`flexItem` задаёт поведение **flex-item** (CSS `flex-grow`, `flex-shrink`, `flex-basis`) на хосте компонента.

Оно **имеет смысл только внутри flex-контейнера** — компонента **Stack** или **любого алиаса, наследующего Stack** (в BFF это, например, `column`, `row`, `surface`, `button`; в проекте или фреймворке могут появиться и другие).

Для **`flexItem` дочернего элемента** важен **именно родитель**: это Stack/алиас с `display: flex`. Направление главной оси смотри у **родителя** — явный `direction` или соглашение алиаса (у `column` / типичного `surface` — vertical, у `row` / `button` — horizontal, если не переопределено).

### Неявный flex-контекст на клиенте (не видно в BFF)

Точки монтирования деревьев с сервера — **content** entry компонент, **overlays** и т.п. — на **клиенте** оборачиваются в **вертикальный flex-контейнер** (аналог `column` / `.stack`: `flex-direction: column`). В конфиге BFF отдельного `column` вокруг корневого массива `content` может не быть, но **`flexItem` у прямых детей корня entry всё равно работает**: главная ось родителя — **сверху вниз**.

Глубже по дереву нужен **явный** Stack/алиас как flex-родитель (или другой клиентский host со stack/flex-column), если элемент не попадает в такой корневой контекст.

**Вне flex-контейнера** (Grid, внутренности компонента без flex-разметки и т.п.) `flexItem` **не меняет раскладку** — для Grid используй **`gridItem`**, иначе оберни содержимое в Stack/алиас.

## Направление и «размер»

**Главная ось** (вдоль которой действуют `grow`, `shrink` и `basis` как размер по main axis) задаётся **`direction` родительского Stack**, а не дочернего:

| Родитель            | Главная ось   | Эффект `grow` / `basis` / `shrink`                                                            |
| ------------------- | ------------- | --------------------------------------------------------------------------------------------- |
| `column` (vertical) | сверху вниз   | вдоль **высоты** (`grow: 1` — занять доступную высоту; `basis` — базовый размер по main axis) |
| `row` (horizontal)  | слева направо | вдоль **ширины** (`grow: 1` — растянуться по ширине; `basis` — базовая ширина)                |

**Поперечная ось** (ширина внутри `column`, высота внутри `row`) **`flexItem` не задаёт** — только **`align`** на родителе, padding и вложенная вёрстка. Узкая колонка по центру экрана: внешний `column` + выравнивание детей по поперечной оси + внутренний stack с нужными `grow` / `basis` **относительно main axis каждого родителя** (часто два уровня `column`).

Не путать: **`flexItem` — размер/доля вдоль main axis родителя**; **`align` на Stack — выравнивание детей**, не замена `flexItem`.

## Поля `FlexItemSpec`

```typescript
flexItem?: {
  basis?: number | DimensionalValue; // grow / shrink — см. ниже
  grow?: number;
  shrink?: number;
};
```

- **`grow`** — доля свободного места **вдоль главной оси** родителя (`0` — не забирать лишнее, `1` — заполнить).
- **`shrink`** — сжатие при нехватке места на главной оси.
- **`basis`** — базовый размер на главной оси:
  - число **`> 1`** — логические **px** (на клиенте в rem);
  - число **`0` или `1`** — `auto` (как в CSS);
  - `{ value, unit }` — явные единицы (`px`, `%`, …).

При **definite** `basis` клиент по умолчанию выставляет `flex-grow: 0` и `flex-shrink: 0`, если `grow` / `shrink` не заданы.

Краткие формы в конфиге: `{ grow: 1 }`, `{ basis: 430 }` (430 px).

## Чеклист агента

- [ ] У компонента с `flexItem` родитель — **Stack/алиас**, **корневой entry-host на клиенте** (вертикальный flex) или вложенный stack
- [ ] Ожидаемый «растяг по ширине/высоте» согласован с **`direction` родителя**, не ребёнка
- [ ] Ограничение ширины: учтён **cross axis** родителя-`column` (`align`, вложенность), а не только `basis` «как ширина»
- [ ] В Grid — **`gridItem`**, не `flexItem`

## Частые ошибки

1. **`flexItem` на корне, родитель не flex** — оберни содержимое в Stack/алиас (например `column({ flexItem: { grow: 1 } }, [...])`).
2. **Узкая колонка не центрируется** — одного `basis` мало; нужен `align` на **родителе-stack** (центр по поперечной оси).
3. **`grow: 1` в `row` ожидали по высоте** — в `row` главная ось горизонтальная, рост идёт по **ширине**; для высоты используй родителя-`column` или явную высоту/цепочку `grow` внутри вертикального stack.

## Связь с `rules`

У Stack можно менять `flexItem` через **`rules`** и `device.*` / `when.*` (например полная ширина на mobile, `basis: 430` на desktop) — overrides применяются к тому же flex-контексту родителя.
